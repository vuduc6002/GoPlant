## 6. Các điểm còn chưa thể chứng minh trong lượt Documentation-Only này

Các hạng mục sau đây chỉ có thể chứng minh bằng code thực thi, integration test hoặc thiết bị thật ở các phase triển khai tương ứng:

1. **Hiệu năng & Query Budget thực tế của G5.5.1:** Tính chất `O(1)` SQL query (0 N+1) và latency `p95 < 300ms` (với dataset `1.000` plants / `20` gardens trên PostgreSQL 16) chưa thể đo vì `MonitoringService` chưa được viết.
2. **Sửa biên giờ `ScheduleService.getTodaySchedules()`:** `ScheduleService` hiện vẫn dùng `23:59:59.999_999_999`; giữ nguyên chưa sửa trong doc-only turn theo đúng guardrail không sửa code.
3. **Hành vi loại bỏ EXIF trên Android / iOS thật & Private Bucket upload:** Hiệu quả thực tế của `expo-image-manipulator` + server-side EXIF stripping và `uploadClient` không gửi JWT sang Storage URL ngoài chỉ chứng minh được khi triển khai G5.5.2b trên thiết bị thật & integration test.
4. **Remote Push Notifications trên Expo SDK 57:** Hoạt động nhận token FCM v1 / APNs `.p8`, A → B token reassignment và deep link khi app killed chỉ chứng minh được sau khi cấu hình EAS Project ID và build **EAS Development Build** ở G5.5.6.
5. **Tác động AI Vision Latency / Quota:** Độ trễ provider AI (15–20s timeout) và độ chính xác parser response chỉ kiểm chứng được khi triển khai Backend AI proxy ở G5.5.5.

## 7. Tóm tắt Phạm vi G5.5.1 Sẵn sàng Triển khai (Lượt tiếp theo)

Sau khi G5.5.0.1 hiệu đính và khóa chuẩn tài liệu, **G5.5.1 — Monitoring Overview & Plant Monitoring MVP** có phạm vi khép kín, tối giản và không phụ thuộc dịch vụ ngoài:

- **Database:** Không thêm migration mới (dùng trực tiếp 11 bảng `V1__initial_schema.sql`).
- **Backend (`Requires Backend/API changes`):** Đúng **2 endpoint** — `GET /api/v1/monitoring/overview` và `GET /api/v1/monitoring/plants/{plantId}` (kiểm tra `owner_id == currentUserId -> 403`), tiêm `Clock`, chuẩn khoảng nửa-mở `[now, startOfTomorrowVn)` và `< now` theo `Asia/Ho_Chi_Minh`, tách `manualCompletedLogs` / `scheduledCompletedLogs` / `scheduledSkippedLogs`, giữ độc lập `UserPlant.healthStatus` vs `GrowthJournal.healthStatus`, SQL query budget `O(1)` (không N+1), trả chuỗi thô `PlantSpecies` dưới mục tham khảo.
- **Frontend:** `monitoringApi.ts`, `monitoringHooks.ts`, `queryKeys.monitoring(userId)`, cập nhật `/monitoring` (chọn vườn -> `/garden-detail`, chọn cây -> `/monitoring/detail?plantId=...`) và `/monitoring/detail` (chỉ nhận `plantId`), dùng `react-native-svg 15.15.4` sẵn có, gắn nhãn *"Chưa kết nối cảm biến IoT"*, đảm bảo cô lập A → B và pass toàn bộ CI gates.
