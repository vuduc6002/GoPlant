## 2. DANH SÁCH FILE THAY ĐỔI & BỔ SUNG

### 2.1. Backend Source Code (`backend/src/main/`)
1. `config/SupabaseStorageProperties.java`:
   - Phân tích nghiêm ngặt enum `ApiKeyType`, ném `IllegalStateException` khi `apiKeyTypeStr` sai giá trị thay vì âm thầm fallback.
   - Trích xuất claim `role` từ Base64/Base64URL JWT payload theo RFC 7519, chỉ chấp nhận `role=service_role`. Từ chối `role=anon`, `role=authenticated` và các format dị thường.
   - Từ chối `sb_publishable_` và `sb_anon_`.
   - Kiểm tra tương thích chéo giữa loại cấu hình và khóa thực tế (`SECRET` vs `LEGACY_SERVICE_ROLE`).
   - Cấu hình finite timeout: `connectTimeoutMs` (1,000–60,000ms, mặc định 10,000ms) và `readTimeoutMs` (1,000–120,000ms, mặc định 30,000ms).
2. `service/storage/SupabaseStorageGateway.java`:
   - Gắn `SimpleClientHttpRequestFactory` với connect và read timeout hữu hạn vào `RestClient`.
   - Bổ sung `sanitizeLogMessage(String raw)` để loại bỏ token, API key, password và bearer credentials khỏi log và thông báo lỗi.
   - Thắt chặt `resolveFullSignedUrl()`: bắt buộc HTTPS, kiểm tra strictly matching host và port với base Supabase URL, cấm protocol-relative `//`, cấm userinfo `@`, yêu cầu tiền tố `/storage/v1/`.
   - Phân biệt lỗi upload xác định (4xx client rejection) và lỗi không xác định (indefinite timeout / I/O error).
3. `service/MediaTransactionCoordinator.java`:
   - Bổ sung record `MediaReadSnapshot` và phương thức `@Transactional(readOnly = true) getReadSnapshot(UUID mediaId, UUID userId)` để snapshot metadata tệp tin và kiểm soát truy cập trong transaction ngắn.
   - Bổ sung `beginReconciliation(UUID mediaId)` khóa dòng và bảo vệ `READY`/`ATTACHED`, trả về `ReconciliationCandidate`.
   - Bổ sung `completeReconciliation(UUID mediaId)` cập nhật trạng thái `DELETED` (tombstone) trong checkpoint riêng.
4. `service/MediaService.java`:
   - Gỡ bỏ hoàn toàn `@Transactional` trên `getReadUrl(UUID mediaId, UUID userId)`: gọi `transactionCoordinator.getReadSnapshot` trong DB transaction ngắn, đóng transaction, sau đó mới gọi HTTP outbound `storageGateway.createSignedUrl`.
   - Trong `uploadMedia()`: phân biệt lỗi không xác định (`isIndefiniteUploadFailure`). Khi upload bị timeout hoặc lỗi mạng, thực hiện best-effort compensation delete nhưng **giữ nguyên bản ghi PENDING** trong DB để background reconciliation đối soát, tránh rò rỉ object lưu trữ muộn.
5. `service/MediaReconciliationService.java` *(File mới)*:
   - Dịch vụ đối soát định kỳ (`@Scheduled`) quét các bản ghi `PENDING` và `DELETING` bị kẹt quá thời gian an toàn (`cutoff`, mặc định 5 phút).
   - Thực hiện HTTP delete ra Supabase Storage ngoài DB transaction.
   - Checkpoint ghi nhận trạng thái `DELETED` (tombstone pattern), bảo toàn audit trail.
6. `repository/MediaRepository.java`:
   - Thêm query `findStuckMediaForReconciliation(@Param("cutoff") OffsetDateTime cutoff)`.
7. `common/exception/StorageUnavailableException.java`:
   - Bổ sung thuộc tính `boolean indefinite` và getter để phân loại lỗi không xác định.
8. `common/media/ImageMetadataProcessor.java`:
   - Xử lý WebP EXIF Orientation: kiểm tra `extractOrientation()`. Do TwelveMonkeys không có WebP writer để xoay raster và re-encode lossless, hệ thống từ chối fail-closed `ValidationException` khi WebP có `orientation > 1` thay vì âm thầm strip EXIF và lưu ảnh sai hướng.
   - Thắt chặt RIFF container parser: lấy `declaredRiffSize` làm giới hạn nghiêm ngặt, từ chối file có trailing bytes hoặc truncated bytes; kiểm tra độ dài tối thiểu của VP8X (>= 10B), VP8 (>= 10B), VP8L (>= 5B & signature 0x2F); từ chối file có nhiều/mâu thuẫn image chunk.
9. `resources/application.properties`:
   - Khai báo đầy đủ các tham số timeout và reconciliation với giá trị mặc định chuẩn mực.

## 3. ROOT CAUSE TỪNG FINDING & GIẢI PHÁP KỸ THUẬT

| STT | Vấn đề phát hiện | Root Cause | Giải pháp kỹ thuật |
| :--- | :--- | :--- | :--- |
| **1** | Supabase API Key chấp nhận chuỗi tùy ý | Cấu hình cũ coi mọi chuỗi không bắt đầu bằng `sb_secret_` là `LEGACY_SERVICE_ROLE`, không kiểm tra claim JWT | Bổ sung parser Base64/Base64URL giải mã payload JWT RFC 7519, bắt buộc claim `"role":"service_role"`, từ chối `role=anon` và các format không xác định. |
| **2** | Storage HTTP client thiếu timeout và log lộ token | `RestClient.builder()` dùng mặc định không giới hạn timeout; log exception in nguyên chuỗi URL chứa token | Cấu hình `SimpleClientHttpRequestFactory` với connect/read timeout; thêm hàm `sanitizeLogMessage` ẩn API key và Bearer token. |
| **3** | DB transaction mở trong lúc gọi Storage HTTP khi lấy Signed URL | `@Transactional(readOnly = true)` bao bọc cả phương thức `getReadUrl()` | Tách transaction thành 2 bước: lấy `MediaReadSnapshot` trong DB transaction ngắn, đóng transaction giải phóng connection pool, sau đó mới gọi HTTP sang Supabase. |
| **4** | Upload timeout làm mất dấu vết bản ghi PENDING | Upload lỗi kích hoạt compensation delete, nếu delete trả 404 thì code cũ xóa luôn bản ghi PENDING | Phân biệt lỗi xác định (4xx) và không xác định (timeout/I/O). Khi lỗi không xác định, giữ nguyên bản ghi PENDING để worker `MediaReconciliationService` định kỳ dọn dẹp. |
| **5** | WebP xoay hướng không được hỗ trợ chuẩn hóa | TwelveMonkeys không có WebP image writer để encode lại ảnh sau khi xoay | Triển khai fail-closed an toàn: từ chối WebP có EXIF Orientation khác 1 với `ValidationException` rõ ràng. |
| **6** | Parser RIFF WebP có thể bị qua mặt | Không kiểm soát giới hạn `declaredRiffSize` và kích thước tối thiểu của các chunk | Enforce declared RIFF boundary, kiểm tra độ dài tối thiểu VP8X (>=10B), VP8L (>=5B), từ chối trailing bytes và xung đột chunk hình ảnh. |
| **7** | Test JPEG orientation chỉ kiểm tra width/height | Không chứng minh được các pixel bên trong thực sự được xoay đúng hướng | Vẽ 4 góc 4 màu (RED, GREEN, BLUE, YELLOW) và kiểm tra màu thực tế tại 4 góc sau khi chuẩn hóa cho cả 8 hướng orientation. |
| **8** | Frontend tạo 2 snapshot phiên khác nhau | `onMutate` và `mutationFn` gọi riêng `resolveMutationSessionOwner` | Capture một `{ ownerUserId, sessionGeneration }` duy nhất đưa vào ref, kiểm tra trước khi gửi request và sau response, ném `SESSION_USER_MISMATCH`. |
| **9** | Multipart boundary có thể bị mất | Đặt thủ công `headers: { 'Content-Type': 'multipart/form-data' }` làm mất tham số `boundary=` | Thêm interceptor xóa header thô `'Content-Type': 'multipart/form-data'` khi gửi `FormData` để adapter tự sinh boundary. |
